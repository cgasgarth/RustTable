# Migration workflow lessons

This records failure patterns observed during strict file-by-file migration work and the checks that prevent recurrence. Keep it concise: add a lesson only when a concrete failure occurs, and replace obsolete prevention rules rather than accumulating history.

## Workflow and orchestration

| Failure pattern | What went wrong | Prevention | Enforceable check |
|---|---|---|---|
| Serial milestone execution | Independent work waited behind one long agent, making full-rewrite throughput impractical. | Fan out source research and non-overlapping implementation across roughly 4–8 agents; reserve one owner for shared hubs and one integrator. One active PR limits delivery, not implementation concurrency. | Every substantial workflow declares file ownership and identifies which stages truly depend on a barrier. |
| Oversized research | Broad discovery consumed excessive tokens and explored UI automation beyond the requested approach. | Give each researcher one responsibility, exact paths, a concise output schema, and explicit exclusions. Do not repeat source mapping already established. | Research prompts cap findings and state what not to investigate. |
| Broad or expensive review | A Sol review was queued for a wide audit when only milestone acceptance boundaries needed review. | Use one Luna-medium reviewer targeted to the changed responsibility and explicit boundaries. Exclude style, optional cleanup, and unrelated code. | Review schemas cap findings; prompts enumerate the exact checks. |
| Same-checkout collision risk | Multiple agents could have edited exhaustive matches and integration hubs concurrently. | Use up to three worker worktrees for independent leaves or diagnostic batches, with exclusive file ownership; keep shared hubs with one canonical-checkout integrator. | Workflow records one owner per writable path; before integration, inspect each worktree diff and reject overlapping ownership. |
| Worker appeared idle | The UI reported an idle agent while it was waiting for a long Cargo test process. | Distinguish model idleness from tool/process idleness before interrupting work. | Inspect the process tree and transcript once; stop only when no useful child process is advancing or a real hang is established. |
| Pathological Cargo cache | Repeated agent builds grew `target/` to 150 GB and more than one million dependency artifacts; each already-built test binary then spent about 18 seconds in loader startup. | Keep agent checks focused, use the changed gate, and clean generated Cargo artifacts when cache size/file count causes measurable startup degradation. | Before blaming hardware or tests, measure `target/` size, dependency-file count, and direct test-binary startup time; use `cargo clean` when the generated cache is the demonstrated bottleneck. |
| Parallel tests exposed a latent race | Nextest load widened a real redb final-handle close/reopen window beyond an arbitrary 16 ms retry budget. Serializing the test would have hidden a production failure. | Investigate whether concurrency failures share mutable fixtures or reveal valid production concurrency before adding test groups. Fix the production boundary when the scenario is valid. | Reproduce the test alone and under load, inspect state isolation, then add deterministic boundary and cross-thread regression coverage for the root fix. |
| Interrupted workflow left live edits | Session exit stopped orchestration after an agent had modified the real checkout. | Treat the working tree as authoritative, inspect `git status` and workflow journal, then resume with the prior run ID. Never discard partial edits automatically. | Resume checklist: one active session, no stale workflow task, journal read, working diff inspected. |
| Duplicate background sessions | Resuming created two conversations targeting the same checkout. | Keep one active migration session per checkout and stop stale sessions before resuming workflows. | Before mutation resumes, verify the background-session list has one writer for the checkout. |
| Agent ran broad gates | Workspace/package-wide checks and broad reverse-dependency closures blocked implementation stages for up to 30 minutes. | Workers have a hard two-minute command budget and run only focused checks expected to fit it. They stop overruns and report remaining validation; the orchestrator batches long changed/full gates after implementation converges. | Workflow prompts state the two-minute limit and prohibit workspace/package-wide gates, the full gate, and broad `cargo xtask check --changed` runs inside workers. |
| Tests raced an unlanded production seam | GTK boundary and runtime-smoke writers were launched in parallel with the workers creating the mount and app handler they needed, so both test leaves correctly stopped without edits. | Put dependent test authors in the stage after interface-producing writers unless the production contract already exists before the workflow starts. Parallelize tests with each other after that barrier, not with their missing dependency. | Before launching a phase, every worker prompt names the concrete existing symbol or artifact it consumes; unresolved producer outputs create an explicit barrier. |
| Doctor false negative | `doctor.sh` expected older Rustup output formatting and reported an installed pinned toolchain/components as missing. | Treat doctor failures as evidence to diagnose, not bypass. Fix the parser in a coherent tooling change; meanwhile verify the exact active toolchain and installed components directly. | Compare `rustup show active-toolchain` and `rustup component list --installed` with `rust-toolchain.toml`; retain the doctor failure as an open defect until fixed. |

## Source-fidelity and integration

| Failure pattern | What went wrong | Prevention | Enforceable check |
|---|---|---|---|
| Invented migration topology | Color Zones registry metadata modeled adjacent migrations although every native legacy branch converts directly to v5. | Derive migration edges from source control flow, not generic version assumptions. | Tests assert the exact ordered `(from, to)` edge set against source evidence. |
| Preserved-channel corruption | A blend helper wrote mask coverage into alpha/spare data although native processing preserves channel 4. | State preserved-channel invariants at plan, blend, evaluator, and pixelpipe boundaries. | Test nontrivial source alpha under partial opacity and mask coverage for bit-exact preservation. |
| Premature generic UI exposure | Registering CPU support caused generic descriptor controls to appear even though the source-derived GTK module was unported. | Model execution support and UI support independently; unavailable UI must remain hidden rather than becoming a plausible substitute. | Registry-to-UI projection tests assert unsupported modules remain unavailable despite CPU execution support. |
| Snapshot identity collision | Color Zones reused Clipping's operation-kind tag. | Allocate snapshot tags centrally and require domain separation for every operation kind. | A centralized uniqueness test fails on duplicate tags. |
| Descriptor order drift | Canonical parameters were emitted in a convenient Rust grouping rather than native v5 declaration order. | Preserve native declaration order unless a documented Rust constraint requires adaptation. | Exact ordered parameter-ID tests compare the full descriptor sequence. |
| Coarse cancellation | Cancellation was checked only around the full Color Zones raster loop. | Long pixel loops must poll cancellation at bounded intervals without changing numerical behavior. | A deterministic test cancels after processing starts and proves no result publication. |
| Capability overclaim | Generated metadata could describe codecs, GPU, or UI more broadly than production behavior supported. | Treat each capability independently and keep unsupported surfaces explicitly false or pending. | Contract tests assert positive CPU capability and negative GPU/UI/import-materialization capabilities together. |
| Agent crossed assigned layer | The initial processing writer also changed pixelpipe files, weakening staged ownership. | Prompts must define allowed leaf files and require the agent to report a blocked integration need instead of editing another owner's shared files. | After each fan-out phase, compare changed files with the ownership map before integration begins. |

## Milestone closeout

Before opening a milestone PR:

1. Confirm the diff matches the workflow ownership map and contains no retained-native or sibling-Darktable changes.
2. Resolve every targeted review finding or record why source evidence disproves it.
3. Run focused checks, generated contracts, and one uninterrupted `cargo xtask check --parallel`.
4. Record only new failure patterns from the milestone and add a prevention check when one exists.
5. Open and squash-merge one milestone PR, sync `main`, then begin the next parallel fan-out.
